# HTTP・シリアル中継

Stream DeckからのHTTP GETを、ESP32へのUSBシリアルコマンドに変換します。通信速度は115200 bps、HTTPの待ち受け先は `127.0.0.1:58912` です。Stream DeckとESP32は同じPCに接続してください。

以下の手順はmacOS向けです。Python 3.9.6で動作確認しています。効果音にはmacOS標準の `afplay` を使います。

## 初回の準備

リポジトリのルートで実行します。

```sh
python3 -m venv bridge/.venv
bridge/.venv/bin/python -m pip install -r bridge/requirements.txt
```

仮想環境とPythonのキャッシュはGitの管理対象から除外しています。

## 起動・終了

ESP32にファームウェアを書き込んでUSB接続し、ポートを確認します。

```sh
ls /dev/cu.*
```

Arduino IDEのシリアルモニターなど、同じポートを使うプログラムを閉じてから起動してください。`--port` は実際のポート名に置き換えます。

```sh
bridge/.venv/bin/python bridge/bridge.py --port /dev/cu.usbserial-10
```

起動したターミナルは開いたままにします。接続できると `Connected to ... at 115200 bps`、HTTPの待ち受け開始時には `HTTP listening on http://127.0.0.1:58912` と表示します。USB未接続でもHTTPは起動し、シリアルへの接続を繰り返します。

`Ctrl+C` で終了し、シリアル接続と再生中の効果音を停止します。ファームウェアを書き込むときは、先に中継プログラムを終了してください。

ポート58912が使用中なら、別のポートを指定できます。変更した場合はStream DeckのURLも変更します。

```sh
bridge/.venv/bin/python bridge/bridge.py \
  --port /dev/cu.usbserial-10 --http-port 58913
```

## 効果音

`--press-sound` で音声ファイルを指定します。省略した場合は無音です。

```sh
bridge/.venv/bin/python bridge/bridge.py \
  --port /dev/cu.usbserial-10 \
  --press-sound /System/Library/Sounds/Glass.aiff
```

自分で用意した音声ファイルも指定できます。パスに空白がある場合は引用符で囲んでください。音だけを試す場合は次を実行します。

```sh
afplay /System/Library/Sounds/Glass.aiff
```

- `PRESS ... rank=1` を受信すると再生します。後続の押下だけでは鳴りません。
- 起動通知 `BOOT` を受信したときも、同じ音を1回再生します。再生中なら止めて鳴らし直し、繰り上がり音の予約もキャンセルします。シリアル接続・再接続だけでは鳴らず、モード通知だけでも鳴りません。接続前に出力された `BOOT` を受信できなかった場合は、起動音は鳴りません。`BOOT` はファームウェアの点灯チェック前に出力されるため、入力受付開始の通知ではありません。
- 不正解で待機中の子機が先頭に繰り上がったときは、不正解の通知を受信してから1秒後に再生します。待機中の子機がいなければ鳴りません。
- 再生中の新しい先頭押下では追加再生をスキップします。繰り上がりの1秒後に再生中の音を止めて鳴らし直します。音の順番待ちは作りません。
- 再生待機中にリセット（モード切替を含む）・正解・切断・終了が発生すると、予約した音をキャンセルします。連続した不正解では、最後の繰り上がりから1秒後に再生します。
- 待機中・再生中もシリアル受信・HTTP処理を継続します。ファイルや `afplay` が見つからない場合は警告を出して無音で動作し、再生エラーもログに表示します。

繰り上がりは、不正解通知の `next_child`（次の1着の子機番号）から判断します。`next_child=0` なら再生しません。中継は着順の履歴を保持しないため、接続前の押下履歴がなくても繰り上がり音を再生できます。この形式に対応したファームウェアを使用してください。

## Stream Deckの設定

標準の「システム → Webサイト（Website）」を4つのキーに割り当てます。各キーで「GET request in background（バックグラウンドでGETリクエスト）」を有効にしてください。

| キー | URL | 送信する文字 | 動作 |
| --- | --- | --- | --- |
| リセット | `http://127.0.0.1:58912/reset` | `r` | 着順・LED・経過時間をリセット |
| 正解 | `http://127.0.0.1:58912/correct` | `o` | 先頭を正解にして全リセット |
| 不正解 | `http://127.0.0.1:58912/wrong` | `x` | エンドレスチャンスでは繰り上げ、1着のみでは全リセット |
| モード切替 | `http://127.0.0.1:58912/toggle-mode` | `m` | モードを切り替えて全リセット |

URLには必ず `http://` を含めてください。末尾の `/` やクエリ文字列は付けません。バックグラウンドGETを使うと、ブラウザを開かずに操作できます。

同じキーを2回押すと2回送信します。特に不正解の連打では次の回答者まで外れるので、1回ずつ操作してください。モード切替も押すたびに切り替わり、2回押すと元のモードに戻ります。

## HTTP応答とログ

別のターミナルから、確認したい操作を1つずつ実行できます。

```sh
curl -i http://127.0.0.1:58912/reset
curl -i http://127.0.0.1:58912/correct
curl -i http://127.0.0.1:58912/wrong
curl -i http://127.0.0.1:58912/toggle-mode
```

| 操作URLの応答 | 意味 |
| --- | --- |
| 202 Accepted | シリアルへの書き込みが完了した。ESP32での実行結果は未確認 |
| 503 Service Unavailable | シリアル未接続、送信失敗、または待機中に接続が切り替わった |
| 404 Not Found | 未定義のURL |
| 501 Not Implemented | GET以外の未対応メソッド |

`TX r`・`TX o`・`TX x`・`TX m` が送信ログ、`RX ...` がESP32からの受信ログです。実行結果は `RX RESET`、`RX JUDGE result=correct ...`、`RX JUDGE result=wrong ...` で確認します。回答者がいない状態で正解・不正解を操作すると、HTTPは202でもESP32から `RX ERROR no_answerer` が返ります。

モード切替の実行結果は `RX MODE mode=first_only` または `RX MODE mode=endless_chance`、`RX RESET` の順に表示されます。起動時は `RX BOOT` に続いて `RX MODE mode=endless_chance` を表示します。1着のみモードの不正解は `next_child=0` に続いて `RX RESET` となり、繰り上がり音は鳴りません。

書き込み失敗時は、一部がESP32に届いている可能性があります。中継側では自動再送しません。再操作の前にLEDと受信ログを確認してください。

## 現在モードの確認

```sh
curl -i http://127.0.0.1:58912/mode
```

HTTP 200で、最後に受信したモードをJSONで返します。

```json
{"mode": "endless_chance"}
```

| `mode` | 意味 |
| --- | --- |
| `"endless_chance"` | エンドレスチャンス。先頭が点滅、2着が点灯し、不正解で繰り上げ |
| `"first_only"` | 1着のみ。後続LEDは消灯し、不正解で全リセット |
| `null` | モード未受信、切断・送信失敗を検出、または再起動の `BOOT` を受信後、モード通知を待っている |

`/mode` はファームウェアからの `MODE` 通知を保持した値を返し、シリアルへのコマンド送信やモード切替は行いません。`/toggle-mode` の202応答だけでは保持値を変更せず、通知を受信してから更新します。`/mode` と `/status` の応答には `Cache-Control: no-store` を付けます。

再接続時は以前のモードを破棄します。接続できても通知がなければ `null` のままです。起動時の通知を受信できなかった場合は、ESP32を再起動するか、問題の開始前にモードを切り替えて通知を確認してください。通常のリセット操作（`r`）ではモード通知は出ません。USB切断を検出するまでの間は、以前の値を返す場合があります。

## 接続状態とUSB再接続

```sh
curl -i http://127.0.0.1:58912/status
```

中継が動作していれば、接続・未接続のどちらもHTTP 200でJSONを返します。

```json
{"status": "connected", "port": "/dev/cu.usbserial-10"}
```

未接続時は `status` が `disconnected` になります。これはPC側のシリアル接続状態で、ESP32の応答や起動完了を確認するものではありません。USBを抜いてから切断を検出するまでの間は、接続中と表示される場合があります。中継が停止していればHTTPにも接続できません。

切断や送信失敗を検出すると接続を閉じ、1秒間隔で指定ポートへの接続を試みます。未接続時の操作や失敗したコマンドは保持せず、復帰後にも再送しません。切断前の受信途中の行、保持していたモード、繰り上がり音の予約も破棄します。

再接続先は起動時に指定したポートです。挿し直してポート名が変わった場合は、ポート名を指定し直して中継を再起動してください。ポートを開く際にESP32がリセットされる場合があるため、問題の途中の状態が保たれることは前提にせず、復帰後にリセットして次の問題を始めてください。

## 実機での確認項目

1. 起動後、`RX MODE mode=endless_chance` が表示され、`/mode` の `mode` が `"endless_chance"` になる。
2. 子機を順に押すと先頭LEDが点滅し、2着が点灯する。Stream Deckの不正解で先頭が消灯し、1秒後に次の回答者が点滅する。正解では全消灯する。
3. 子機の着順がある状態でStream Deckのモード切替を押すと、`RX MODE mode=first_only`、`RX RESET` が表示され、全消灯する。`/mode` の `mode` が `"first_only"` になる。
4. 1着のみモードで子機を順に押すと、先頭だけが点滅し、後続は消灯する。不正解では `next_child=0`、`RESET` が表示され、全消灯する。次の押下の `elapsed_ms` が不正解によるリセットからの時間になる。正解でも全消灯する。
5. モード切替をもう一度押すとエンドレスチャンスに戻り、着順・LED・経過時間がリセットされる。シリアルモニターから直接 `m` を送っても同様に切り替わる（中継とシリアルモニターは同時に同じポートを開かない）。
6. 回答者不在で正解・不正解を操作すると `RX ERROR no_answerer` が返る。通常のリセット・正解・不正解ではモードが変わらない。
7. 効果音を指定すると先頭の押下で鳴る。エンドレスチャンスでは繰り上がりがある場合、不正解通知から1秒後にも鳴り、待機中にモードを切り替えると予約がキャンセルされる。1着のみモードの不正解では繰り上がり音は鳴らない。
8. USBを抜くと、切断検出後に `/status` が `disconnected`、`/mode` の `mode` が `null` になり、切替を含む操作URLは503を返す。
9. 同じポート名でUSBを挿し直すと `connected` に戻る。新しいモード通知を受信するまでは `/mode` の `mode` が `null` になり、通知後に更新される。切断中の操作は再送されない。
10. `Ctrl+C` で終了後、シリアルモニターや書き込みツールでポートを利用できる。

## 困ったとき

| 症状 | 確認すること |
| --- | --- |
| Stream Deckを押してもHTTPログが出ない | URLの `http://`、ポート番号、キーへの割り当て、中継が起動しているか |
| 404が出る | URLのパス、末尾の `/`、クエリ文字列 |
| 接続失敗の警告が続く・503になる | USB接続、`--port` の値、シリアルモニターなど他のプログラムによる使用 |
| 起動時にHTTPの待ち受けが失敗する | 同じポートで既に中継などが起動していないか |
| 効果音が鳴らない | `--press-sound`、音声ファイル、PCの音量・出力先、再生エラーのログ |

## 自動テスト

リポジトリのルートで実行します。HTTPテストはローカルの一時ポートを使います。ESP32実機や実際の音声再生は使用しません。

```sh
bridge/.venv/bin/python -m unittest discover -s bridge -v
```
